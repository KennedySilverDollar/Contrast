# 0. 最初に調べる（読み取りのみ）

# 1. Cargo workspace
- ルートに [workspace] があれば、members に "crates/contrast-core" を追加するだけにする。
- 無ければ、次の最小のルート Cargo.toml を作る。

  resolver = "2"
  members = ["crates/contrast-core"]

# 2. crates/contrast-core/Cargo.toml
次の内容で作る（version と edition は変えない）。

edition = "2021"

[lib]

expect_used = "deny"
panic = "deny"

[dependencies]

# 4. CI: .github/workflows/core.yml
ジョブは 3 本。トリガーは push と pull_request。アクションは公式のメジャータグで固定する。
- verify: checkout → Rust toolchain（rust-toolchain.toml に従う）→ scripts/verify.sh
- kani: checkout → model-checking/kani-github-action → `cargo kani -p contrast-core`
  （この時点では verification/spec にハーネスが無いので、ハーネス 0 件でも失敗しない設定にできるか確認し、
   できなければ `continue-on-error: true` を付けて、報告に理由を書く）
- mutants-coverage: checkout → cargo-mutants と cargo-llvm-cov を導入 →
  `cargo mutants -p contrast-core --in-diff <PR の差分>` と
  `cargo llvm-cov -p contrast-core --all-features --fail-under-lines 95`
  （コードが空の今は意味がないので `if: false` を付けて無効にしておき、P8 で有効にする、とコメントに書く）
アクションのバージョンやオプションに自信がなければ、推測で書かず公式ドキュメントを確認する。

# 5. やらないこと
- docs/、scripts/、prompts/ を変更しない。CLAUDE.md と .claude/ を作らない。
- flake.nix は変更しない。足りないツール（cargo-kani, cargo-mutants, cargo-llvm-cov,
  cargo-semver-checks）は、報告に「devShell に必要」と書くだけにする。
- ツールチェーンやターゲットが入っておらず作業が止まったら、環境を勝手に直さず、状況を報告して止まる。
- rm、git reset、git checkout、git restore など破壊的な操作をしない。ファイルを削除しない。
- git add、git commit、git push をしない。コミットは人間が差分を見てから行う。
