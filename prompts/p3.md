# フェーズ P3: エンティティと不変条件検査

## 読むもの
- docs/core-spec.md の 3 節、4 節、7 節「暫定決定」、9 節「モジュール構成」
- crates/contrast-core/tests/spec/spec_invariant.rs

## やること
1. src/domain/ に次を実装する。
   - output.rs: `Output { id, key, name: OutputName, geometry: Rect, shown: WorkspaceId }`。
     作業領域は D4 により geometry と同じ。`work_area()` を用意する。
   - workspace.rs: `Workspace { id, index: WorkspaceIndex, order: Vec<WindowId>, focus_history: Vec<WindowId> }`。
   - window.rs: `Window { id, key, meta: WindowMeta, state: WindowState, workspace: WorkspaceId, floating_rect: Option<Rect> }`、
     `WindowMeta`、`WindowState { Tiled, Floating, Fullscreen }`。
   - state.rs: `State`。出力・ワークスペース・窓を BTreeMap で持ち、KeyMap 2 本（出力・窓）、
     IdGen、フォーカス（Option<WindowId>）、各窓の配置済み矩形（BTreeMap<WindowId, Rect>）を持つ。
     `Clone` と `PartialEq` を derive する。
   - `State::new(config: &CoreConfig)` は D1 に従い workspace_count 個のワークスペースを作る。
2. src/invariant.rs に `InvariantViolation`（I1〜I6 に対応する variant、どの ID で破れたかを持つ）と
   `check_invariants(&State) -> Result<(), InvariantViolation>` を実装する。
   不変条件 1 つにつき private 関数 1 つ（check_i1 〜 check_i6）に分け、I1 から順に検査して最初の違反を返す。
3. 仕様テストが State を直接組み立てられるよう、`#[cfg(any(test, feature = "invariants"))]` で
   `State` の各フィールドを操作するテスト用ビルダ `StateBuilder` を公開する（本番 API には出さない）。
4. 不足しているテストは tests/impl_invariant.rs に足す。

## やらないこと
- application/、layout/、policy/ にはまだ手を出さない。
- State に状態遷移ロジック（窓の追加など）を書かない。それは P4 の handler の仕事。

## 完了条件
- scripts/verify.sh --full が緑。spec_invariant.rs の否定テストがすべて該当 variant を検出する。
- CLAUDE.md の「報告の形式」で報告して終わる。
