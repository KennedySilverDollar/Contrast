## 公開 API（仕様テストと Kani ハーネスが前提にしている形）
```rust
// domain/id.rs
pub trait IdKind: Copy + Ord {
    fn from_raw(raw: u64) -> Self;
    fn raw(self) -> u64;
}
pub struct OutputId(u64);     // Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash 不要
pub struct WindowId(u64);     // 同上
pub struct WorkspaceId(u64);  // 同上。3 つとも IdKind を実装する
pub struct WorkspaceIndex(u8);
impl WorkspaceIndex { pub fn new(n: u8) -> Self; pub fn get(self) -> u8; }  // Debug, Clone, Copy, PartialEq, Eq, Ord
pub struct ExternalKey(u64);
impl ExternalKey { pub fn new(raw: u64) -> Self; }                          // Debug, Clone, Copy, PartialEq, Eq, Ord
pub enum EntityId { Output(OutputId), Window(WindowId) }                    // Debug, Clone, Copy, PartialEq, Eq

pub struct IdGen<T: IdKind> { /* next: u64 */ }
impl<T: IdKind> IdGen<T> {
    pub fn new() -> Self;                       // 最初の ID は raw = 1
    pub fn starting_at(next_raw: u64) -> Self;  // テストと Kani 用。次に払い出す raw 値を指定
    pub fn next(&mut self) -> Result<T, CoreError>;
}
// next: 現在値が u64::MAX なら Err(IdExhausted)（以後も同じ）。それ以外は現在値を返して 1 進める。
// 進める計算は checked_add。パニックしない。

pub struct KeyMap<T: IdKind> { /* BTreeMap<ExternalKey, T> と BTreeMap<T, ExternalKey> */ }
// Debug, Clone, PartialEq, Eq, Default
impl<T: IdKind> KeyMap<T> {
    pub fn new() -> Self;
    pub fn insert(&mut self, key: ExternalKey, id: T) -> Result<(), CoreError>;
    pub fn remove_by_key(&mut self, key: ExternalKey) -> Result<T, CoreError>;
    pub fn id_of(&self, key: ExternalKey) -> Option<T>;
    pub fn key_of(&self, id: T) -> Option<ExternalKey>;
    pub fn len(&self) -> usize;
    pub fn is_empty(&self) -> bool;
    #[cfg(any(test, kani, feature = "invariants"))]
    pub fn is_bijective(&self) -> bool;
}
```
- insert: key か id のどちらかが既に登録済みなら `Err(DuplicateKey)`。**どちらも確認してから**書き込み、
  Err のときは対応表を一切変えない（強い例外保証）。
- remove_by_key: 未登録なら `Err(UnknownKey)`。成功時は両方向のエントリを消す。
- is_bijective: 2 つの BTreeMap の要素数が等しく、すべての (k, v) について逆引きが (v, k) に戻ること。

```rust
// error.rs
#[derive(Debug, Clone, PartialEq, Eq)]
#[non_exhaustive]
pub enum CoreError {
    UnknownKey, DuplicateKey, NoFreeWorkspace, WorkspaceIndexOutOfRange,
    NoFocusedWindow, IdExhausted, GeometryOverflow, Layout(LayoutError),
}
```
- 仕様 6 節の variant をすべて定義する（この時点で使わないものも含む）。これ以外は足さない。
- `core::fmt::Display` と `core::error::Error` を実装する。メッセージは日本語でも英語でもよいが、空文字にしない。
- `impl From<LayoutError> for CoreError` を実装する。

## やること
1. src/domain/id.rs に上の API を実装する。ID 型のフィールドは private。`IdKind` を 3 つの ID 型に実装する。
2. src/error.rs に CoreError を追加する（LayoutError は変更しない）。
3. src/lib.rs に `pub mod id;` を domain の inline mod に足し、次を再エクスポートする。
   `CoreError, EntityId, ExternalKey, IdGen, IdKind, KeyMap, OutputId, WindowId, WorkspaceId, WorkspaceIndex`。
4. src/verification/extra/mod.rs に `pub mod id;` を足し、src/verification/extra/id.rs を作る。
   足すハーネスの例: WorkspaceIndex の往復、IdGen<OutputId> と IdGen<WorkspaceId> での枯渇、
   KeyMap<OutputId> での全単射。`kani::any()` の範囲は `kani::assume` で絞り、`#[kani::unwind(N)]` を明示する。
5. tests/impl_id.rs に、仕様テストが触れていない境界を足す
   （1000 回の払い出しで重複なし、同じキーを繰り返し登録・削除しても len が合う、など）。
6. 全公開項目に doc コメントを書く。モジュール冒頭に守る不変条件の番号（I6）を書く。

## やらないこと

- tests/spec/、verification/spec/ は読むだけ。仕様テストが通らなければ、テストではなく実装を直す。
  直せないと判断したら docs/questions.md に書いて止まる。
- domain/ の他のスタブ（output.rs、window.rs、workspace.rs）、invariant.rs には手を付けない（P3 の対象）。
- 公開 API の名前・引数・戻り値を、上の定義から変えない。依存クレートを追加しない。
