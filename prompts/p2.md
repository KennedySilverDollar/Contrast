# フェーズ P2: ID と対応表

## 読むもの
- docs/core-spec.md の 3 節、4 節の I6、6 節「エラー」
- crates/contrast-core/tests/spec/spec_id.rs
- crates/contrast-core/src/verification/spec/id.rs

## やること
1. src/domain/id.rs に次を実装する。
   - `OutputId`, `WindowId`, `WorkspaceId`: u64 の newtype。Copy, Ord, Debug。
   - `WorkspaceIndex`: u8 の newtype。
   - `ExternalKey`: u64 の newtype。公開コンストラクタ `ExternalKey::new(u64)`。
   - `EntityId`: `Output(OutputId)` / `Window(WindowId)`。
   - `IdGen<T>`: `next(&mut self) -> Result<T, CoreError>`。1 から単調増加。
     u64::MAX に達したら `Err(CoreError::IdExhausted)` を返し、以後も同じ。
   - `KeyMap<T>`: ExternalKey と ID の双方向表。BTreeMap 2 本で持つ。
     `insert(key, id) -> Result<(), CoreError>`（key か id が既にあれば DuplicateKey、表は不変）、
     `remove_by_key(key) -> Result<T, CoreError>`（なければ UnknownKey）、
     `id_of(key) -> Option<T>`、`key_of(id) -> Option<ExternalKey>`、`len()`。
2. src/error.rs に `CoreError` を作り、仕様 6 節の variant をすべて定義する
   （この時点で使わないものも含む）。`LayoutError` は `CoreError::Layout` で包む。
   Debug と core::fmt::Display を手で実装する。
3. KeyMap 内部の全単射を検査する `fn is_bijective(&self) -> bool` を `#[cfg(any(test, kani))]` で用意する。
4. 不足している性質は tests/impl_id.rs と src/verification/extra/id.rs に足す。
