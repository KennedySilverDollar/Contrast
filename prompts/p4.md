## やること
1. layout/mod.rs に `Layout` trait、policy/mod.rs に `Policy` trait と `Placement`、`PlacementContext` を
   仕様どおりのシグネチャで定義する。実装はまだ書かない（P5・P7）。
   テスト用に `tests/impl_support/` へ、単純な Layout（全窓に作業領域を縦に均等分割）と
   常に `Placement { workspace: None, state: Tiled, focus: true }` を返す Policy を置いてよい。
2. application/ に `Core`, `CoreConfig`, `Command`, `Action`, `Direction`, `Effect`, `Applied`,
   `StateView`, `StateSnapshot` を実装する。
3. `Core::apply` は次の手順に固定する。
   1. `self.state.clone()` で作業用 State を作る。
   2. Command に対応する handler を呼ぶ。handler は作業用 State を変更し、Effect を返す。
   3. 再レイアウト: 表示中の全ワークスペースについて Tiled 窓の矩形を Layout で再計算し、
      Floating（D8）と Fullscreen（D9）の矩形も決める。前回と変わった窓だけ Configure を出す。
   4. Effect 列を仕様の順序に並べ替え、Damage を D15 に従って付ける。
   5. いずれかで Err なら作業用 State を捨てて Err を返す。成功時だけ self.state に差し替える。
4. handlers/ に次を 1 ファイルずつ実装する: output_added, output_removed, output_changed,
   window_mapped, window_unmapped, window_meta_changed。
   Action はこのフェーズでは `Ok(Applied { effects: vec![] })` を返すだけにする（P6 で実装）。
5. `check_invariants()` と `snapshot()` は `#[cfg(any(test, kani, feature = "invariants"))]` で公開する。
6. 状態機械テストを通す。失敗したら実装を直す。テスト側は変えない。
